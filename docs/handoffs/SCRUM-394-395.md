## Implemented and verified without persistence

| Acceptance | Foundation behavior |
|---|---|
| Sample request lifecycle | Draft -> Submitted -> In Production -> Ready -> Sent to Customer -> Approved / Changes Requested; only Draft can cancel; only Changes Requested can reopen Draft. |
| Customer feedback and rounds | Nonblank change feedback, actor/time and the exact reviewed specification are retained. Reopening increments the round once. Stale version/round and stale production callbacks are rejected. |
| Approval lock | Submitted specifications cannot be edited. Approved is terminal. Immutable review captures snapshot ID, SHA-256 checksum and blank SKU, quantity and due date. Rehydration validates the history and emits no event. |

| ORDER creation | `OrderProductionService.receive` accepts the existing `OrderLinesReleasedForProduction`, validates every line and reference before any insert, and creates PENDING_PREPRESS orders by order-line source. |
| New/repeat designs | Explicit approval must match customer + design snapshot + checksum + blank. A null approval ID for a repeat design resolves an existing approval for that customer/design/blank; it never bypasses the sample gate. Quantity/due date may differ from the physical sample. |
| Duplicate/replay | Source identity is independent of event delivery. Existing payload must match; changed customer/order/warehouse/specification/approval conflicts. Atomic insert-or-get must return the persisted winner. Replay preserves completed workflow state and does not reread artifact bytes. |
| Batch/race contract | Entire batch is validated before writes; insert claims are ordered by source ID. A conflicting concurrent winner is rejected. Database atomicity/races are explicitly not proven by these mock-based tests. |
| Access control | Shared server-side `PermissionChecker` is used. Anonymous/permission failures precede loading. Customer identity is resolved through `customer::api`; even a CUSTOMER with ALL scope cannot access another customer's sample or edit drafts. | Module boundary | New `production` module only imports `customer::api`, `design::api`, shared common/contracts. No order, inventory, fulfillment or identity internals are imported. |
